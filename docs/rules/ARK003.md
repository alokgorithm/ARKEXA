# ARK003 `agent-output-to-path`

|  |  |
|---|---|
| Severity | high |
| OWASP Agentic Top 10 (2026) | ASI05 Unsafe Tool Invocation |
| Introduced in | v0.1 |

Model output builds a file path, a branch name, or a checkout ref.

Model output is used to build a filesystem path, a git branch name, or the ref
a checkout step resolves. None of those are free-form strings:

  * a path can traverse upwards with ../ and overwrite a workflow file
  * a branch or ref can be pointed at a fork, so a later step checks out and
    runs code the attacker chose
  * a filename can be .github/workflows/anything.yml, which turns a single
    write into persistent execution

The model does not have to be malicious. It only has to be talked into
emitting a string, which is what prompt injection is for.

Note the difference from ARK002: there the model output is parsed as script.
Here it is a perfectly ordinary argument, in a position where the argument
names a location. Writing model output *into* a fixed file is fine, which is
why this rule looks at the path, not at the content.

Fix: derive paths from values you control (a run id, a hash), validate against
an allowlist, or confine writes to a directory created for the purpose.

## Reported

```yaml
# ARK003: the model chooses the branch a later step checks out.
name: Autofix
on:
  issues:
    types: [opened]

jobs:
  fix:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - id: ai
        uses: actions/ai-inference@v1
        with:
          prompt: Which branch should we patch?
      - name: Check out what the model picked
        uses: actions/checkout@v4
        with:
          ref: ${{ steps.ai.outputs.response }}
      - name: Branch from it
        env:
          TARGET: ${{ steps.ai.outputs.response }}
        run: git checkout -b "$TARGET"
```

## Not reported

```yaml
# Safe: the model answer is content, not a location. The path is fixed and the
# branch name is derived from the run id.
name: Autofix
on:
  issues:
    types: [labeled]

jobs:
  fix:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - id: ai
        uses: actions/ai-inference@v1
        with:
          prompt: Suggest a patch.
      - name: Save the suggestion
        env:
          ANSWER: ${{ steps.ai.outputs.response }}
        run: |
          printf '%s' "$ANSWER" > suggestion.md
          git checkout -b "autofix/${{ github.run_id }}"
```

Both files live in [`tests/fixtures`](../../tests/fixtures) and are checked on
every run, so the safe one is a promise, not a claim.

## Reachability

This rule, like every other, is reported only when the job it lives in can be
triggered by the level you asked for. By default that means `external`: any
GitHub account. Add `--reachability all` to see findings that need write
access to reach.

## Suppressing it

```yaml
# .arkexa.yml
ignore:
  - rule: ARK003
    path: .github/workflows/example.yml
    reason: why this one is acceptable
```

A `reason` is required. An ignore without one is reported and not applied.
