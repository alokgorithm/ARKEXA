# ARK002 `agent-output-to-shell`

|  |  |
|---|---|
| Severity | critical |
| OWASP Agentic Top 10 (2026) | ASI05 Unsafe Tool Invocation |
| Introduced in | v0.1 |

Model output is interpolated into run: or piped into an interpreter.

A model wrote text, and that text ends up inside a `run:` block, a pipe into a
shell, or an `eval`. Model output is not trusted input: it is a function of the
prompt, and the prompt is often a function of something an outsider wrote. Once
that text is a command line, the injection is a shell injection.

`${{ steps.ai.outputs.text }}` inside `run:` is the worst shape, because the
expression is substituted into the script before the shell ever sees it, so no
amount of quoting inside the script helps.

Fix: put the model output in an environment variable and reference it as
"$VAR", never interpolate it into the script body, and never pipe it into
bash, sh, eval, python -c or node -e.

## Reported

```yaml
# ARK002: model output is interpolated straight into a run: block.
name: Suggest
on:
  issue_comment:
    types: [created]

jobs:
  suggest:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - id: ai
        uses: actions/ai-inference@v1
        with:
          prompt: ${{ github.event.comment.body }}
      - name: Post it
        run: |
          echo "${{ steps.ai.outputs.response }}"
```

## Not reported

```yaml
# Safe: the model answer goes through env and is never parsed as script.
name: Suggest
on:
  issue_comment:
    types: [created]

jobs:
  suggest:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - id: ai
        uses: actions/ai-inference@v1
        with:
          prompt: ${{ github.event.comment.body }}
      - name: Post it
        env:
          ANSWER: ${{ steps.ai.outputs.response }}
        run: |
          printf '%s' "$ANSWER" > answer.txt
```

Both files live in [`tests/fixtures`](../../tests/fixtures) and are checked on
every run, so the safe one is a promise, not a claim.

## Reachability

This rule, like every other, is reported only when the job it lives in can be
triggered by the level you asked for. By default that means `external`: any
GitHub account. Add `--reachability all` to see findings that need write
access to reach.

## Suppressing it

```yaml
# .arkexa.yml
ignore:
  - rule: ARK002
    path: .github/workflows/example.yml
    reason: why this one is acceptable
```

A `reason` is required. An ignore without one is reported and not applied.
