# ARK004 `agent-autoapprove`

|  |  |
|---|---|
| Severity | high |
| OWASP Agentic Top 10 (2026) | ASI02 Tool Misuse and Excessive Agency |
| Introduced in | v0.1 |

Agent runs with approvals disabled or a wildcard tool allowlist.

The agent is started with its confirmation prompts disabled, or with a tool
allowlist that is really a wildcard. In CI there is no human at the terminal, so
these flags are often added to stop the job hanging - which is exactly why they
are dangerous: the flag that unblocks the job also removes the only control
that stood between a prompt and a tool call.

Severity does not depend on the prompt being tainted. An agent with no approval
gate and a token is a standing risk; taint decides how easy it is to aim.

Fix: allowlist the specific tools the job needs, run the agent in a container
without credentials, or keep approvals on and have the job fail rather than
proceed unattended.

## Reported

```yaml
# ARK004: the agent runs with its approval prompts disabled.
name: Nightly agent
on:
  issue_comment:
    types: [created]

jobs:
  work:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - name: Let it work
        run: claude --dangerously-skip-permissions -p "Fix the failing test"
```

## Not reported

```yaml
# Safe: the agent runs with an explicit, narrow tool allowlist.
name: Nightly agent
on:
  issue_comment:
    types: [created]

jobs:
  work:
    runs-on: ubuntu-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4
      - name: Let it work
        run: claude --allowedTools "Read,Grep" -p "Fix the failing test"
```

Both files live in [`tests/fixtures`](../../tests/fixtures) and are checked on
every run, so the safe one is a promise, not a claim.

## Reachability

This rule, like every other, is reported only when the job it lives in can be
triggered by the level you asked for. By default that means `external`: any
GitHub account. Add `--reachability all` to see findings that need write
access to reach.

## Suppressing it

```yaml
# .arkexa.yml
ignore:
  - rule: ARK004
    path: .github/workflows/example.yml
    reason: why this one is acceptable
```

A `reason` is required. An ignore without one is reported and not applied.
